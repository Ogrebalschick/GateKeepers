# Changelog

## 2.4.0 — release candidate finalized

- Переведён Layer 1 на `SGDClassifier(loss="log_loss")` с общим word/character TF-IDF-векторизатором для трёх классификационных голов.
- Унифицировано представление признаков обучения и инференса: нормализованный текущий запрос, роль, история и вложения формируются одинаково и не дублируются.
- Категория угрозы для `block` выбирается среди 12 категорий угроз; `none` и `sensitive_action` не конкурируют с угрозами при классификации заблокированного запроса.
- Уровень риска обучается на `block` и `confirm`, без доминирующего класса `none`.
- Расширена нормализация смешанных кириллическо-латинских homoglyph и leetspeak-вариантов.
- История сканируется по отдельным пользовательским сообщениям; безопасный анализ и цитирование атак не превращаются автоматически в активную инструкцию.
- Усилены правила indirect injection, system prompt override, privilege escalation, data exfiltration, harmful content, fraud/social engineering и production tool abuse.
- Уточнено разделение безопасного защитного анализа и опасного создания/выполнения инструментов для сокрытия следов.
- Добавлены безопасные маршруты для анализа логов, учебного разбора SQL injection, тестирования миграций в disposable dev-среде, запросов доступа через SRE и анализа вложенных документов.
- Добавлены 9 регрессионных тестов по обнаруженным ложным блокировкам и пропускам.
- `validate_model.py` отдельно показывает full-pipeline OOF и model-only OOF.
- Добавлен 72-сценарный regression suite с прямыми атаками, hard negatives, RBAC, историей и вложениями.
- Сохранён API-контракт `/v1/check`; внешний LLM API не используется.
- Контрольные проверки финальной копии: 145 тестов; официальный evaluator 70/70; challenge suite 72/72.
